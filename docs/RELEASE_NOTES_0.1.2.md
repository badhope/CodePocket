# CodePocket 0.1.2 — 引擎连接与慢设备启动修复

**版本号**：0.1.2（versionCode 42）  
**发布日期**：2026-11-25  
**定位**：0.1.1 的真实验收暴露出的连接超时修复；保留 0.1.1 的全部移动布局改造，不改 `:engine` 独立进程边界。

## 问题

在 x86_64 Android 15 模拟器（API 35，TCG 纯软件模拟）上启动 0.1.1 release 时，输出面板报：

```text
[CodePocket] Python 原生运行时初始化失败，JavaScript/Lua 仍可运行；请点「自检」查看缺失项。
```

自检同时显示 CPU 架构、标准库、解释器、JNI 桥均可用，仅 C 扩展模块红。根因不是运行时资源缺失，而是 `:engine` 进程冷启动在本机超过主进程原先的 8 秒 Binder 等待；连接被判定失败后，准备步骤没有真正完成。

## 修复

- `RemoteNativeEngine` 的 Binder 连接等待从 **8 秒提高到 30 秒**，避免把慢启动误判成运行时损坏。
- 首次 prepare 的总等待从 **120 秒提高到 180 秒**，覆盖标准库解压与 50+ 个 C 扩展从 APK 抽取；进度条持续可见。
- 不改 0.1.0 的独立进程架构：主进程仍只持有 `RemoteNativeEngine`，`libpython` / `libpybridge` 仍在 `:engine` 加载。
- 0.1.1 的紧凑顶栏、按宽度分栏、抽屉宽度 200–272dp、窄屏三列快捷动作全部保留。

## 真实验证

- 在 x86_64 Android 15 模拟器安装 0.1.2 release，完成首次准备后打开 `main.py`：
  - 标准输出：`Hello from CodePocket!`
  - 计算结果：`1^2 + 2^2 + ... + 10^2 = 385`
  - 进程退出码 0，耗时约 1.3 秒
- 同轮首次准备在 TCG 模拟器上耗时超过 2 分钟；这是纯软件模拟的耗时，不作为手机性能结论。
- 紧凑顶栏、更多菜单、抽屉三列、横屏两栏均有真实截图；截图见交付页。

## 明确边界

- **仍无 ARM64 真机验收**：本轮只有 x86_64 模拟器真实运行，不冒充物理 ARM64 结果。
- 不做 Gradle/Java/Kotlin 工程构建、完整 LSP、原生 wheel ABI；边界与 0.1.0/0.1.1 相同。
- 首次准备的 180 秒只是容错上限，不代表每次启动都慢；正常缓存后启动会跳过解压与抽取。
